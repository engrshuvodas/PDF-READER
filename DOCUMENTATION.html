PDF Voice Reader Architecture

In-depth technical documentation covering the PDF.js coordinate transformation pipeline, real-time Web Speech API word boundary synchronization, Bengali (বাংলা) Unicode classification, and dual-engine voice routing.

1. System Overview

PDF Voice Reader is an autonomous, 100% client-side text-to-speech web application built with React 18, Vite 6, PDF.js, and the browser-native Web Speech API.

🔒 100% Client-Side Privacy

Zero backend servers and zero paid APIs. Documents and extracted text are processed exclusively in the user's browser memory.

⚡ Millisecond Audio-Visual Sync

Binds SpeechSynthesisUtterance.onboundary events directly to PDF bounding boxes for karaoke-style highlighting.

🇧🇩 Dual-Language Auto-Switching

Seamlessly detects Bengali (বাংলা) and English words, automatically routing them to matching native voice engines.

📱 Universal Responsiveness

Engineered for smartphones (360px–480px), tablets (768px–1024px), laptops, and multi-monitor setups.

2. Coordinate Normalization & Word Extraction Pipeline

PDF coordinate systems have their origin $(0,0)$ at the bottom-left, whereas HTML Canvas and browser CSS layout systems originate from the top-left.

2.1 Transformation Matrix to Normalized Coordinates

Calling page.getTextContent({ includeMarkedContent: true }) yields text items with a 6-element transformation matrix: 

// Transform Matrix: [scaleX, skewY, skewX, scaleY, tx, ty]
const tx = item.transform[4];
const ty = item.transform[5];
const itemHeight = Math.abs(item.transform[3]) || item.height || 12;
const itemWidth = item.width || (item.str.length * itemHeight * 0.5);

// Convert bottom-left origin to normalized top-left space (0.0 to 1.0)
const normX = Math.max(0, tx / pageWidth);
const normY = Math.max(0, (pageHeight - ty - itemHeight) / pageHeight);
const normW = Math.min(1.0 - normX, itemWidth / pageWidth);
const normH = Math.min(1.0 - normY, itemHeight / pageHeight);

2.2 Proportional Sub-Word Tokenization

When a single text item contains multiple words (e.g. "The quick brown fox"), word bounding boxes are computed proportionally based on character offsets: 

const startRatio = charStartInItem / item.str.length;
const lengthRatio = word.length / item.str.length;

const wordNormX = item.normX + startRatio * item.normW;
const wordNormW = Math.max(0.005, lengthRatio * item.normW);
const wordNormY = item.normY;
const wordNormH = item.normH;
💡
Normalized Space Independence: Storing boxes as percentage floats $(0.0 \le x, y, w, h \le 1.0)$ enables dynamic viewport resizing and pinch-to-zoom without recalculating word bounding boxes.

3. Real-Time Speech Synchronization Engine

Managed by the custom useTTS React hook, speech synthesis coordinates with the visual layer using boundary event mapping.

3.1 onboundary Event Resolution

During vocalization, the browser fires utterance.onboundary containing event.charIndex into the spoken string. 

utterance.onboundary = (event) => {
  const charIndex = event.charIndex || 0;
  
  // Find word where charStart <= charIndex < charEnd
  const matchedWord = section.words.find(
    (w) => charIndex >= w.charStart && charIndex < w.charEnd
  ) || findClosestWord(section.words, charIndex);

  if (matchedWord) {
    setActiveWordId(matchedWord.id);
    setActiveWord(matchedWord);
  }
};

3.3 Chrome Garbage Collection Keep-Alive

⚠️
Chromium Engine Quirk: Long utterances (> 15 seconds) can pause unexpectedly due to internal garbage collection. useTTS incorporates a 12-second non-disruptive heartbeat pulse (pause() / resume()) that guarantees uninterrupted smooth playback.

4. Bilingual (বাংলা ও English) Auto-Switching System

Implemented in languageService.js, the engine inspects Unicode code points to detect language shifts on the fly:

Language Script Unicode Block Range Default TTS Locale Preferred Voice Search
Bengali (বাংলা) \u0980 to \u09FF bn-BD / bn-IN Bangla, Bengali, বাংলা, Microsoft Bashkar
Latin / English a-z, A-Z en-US Google US English, Microsoft David, Natural

4.1 Mixed Paragraph Speech Chunking

When reading paragraphs with mixed sentences (e.g. "AI এখন মানুষের অংশ। This is powerful."), the text is partitioned into sequential language segments. Segment 1 plays with the Bengali voice engine; upon completion (onend), Segment 2 automatically continues with the English voice engine without losing word tracking.

5. Custom Text-to-Speech Document Mode

Users can copy-paste text or upload .txt / .md files:

  • textParserService.js transforms raw text into structured paragraph cards.
  • TextViewer.jsx presents a clean reading interface with per-paragraph inline 🔊 play buttons.
  • Every word is wrapped in an interactive <span> that supports click-to-read and glowing karaoke highlight boxes.

7. Service & Hook API Reference

pdfService.js

  • loadPdfDocument(source): Loads binary PDF into a PDF.js proxy.
  • extractDocumentStructure(pdfDoc): Parses multi-page lines, sections, and word geometry.
  • renderPageToCanvas(page, canvas, scale): High-DPI canvas rendering.

languageService.js

  • detectLanguage(text): Detects primary language ('bn-BD' vs 'en-US').
  • segmentSectionByLanguage(section): Partitions mixed text into language chunks.
  • findBestVoiceForLanguage(voices, lang, preferredURI): Resolves optimal voice object.

useTTS.js Hook State

  • playSection(section, startIndex): Starts speech synthesis.
  • pause() / resume() / stop(): Audio controls.
  • togglePlayPause(): Toggles playback state.
  • nextSection() / prevSection(): Skips between sections.

8. Troubleshooting & FAQ

Q: Why is boundary highlighting slightly delayed on Safari or Firefox?

Google Chrome and Microsoft Edge provide precise millisecond-accurate charIndex boundary updates. Apple Safari and Mozilla Firefox fire boundary events with approximate sentence/chunk timing. The application remains fully functional across all browsers.

Q: How does offline Bengali voice synthesis work?

If no native offline Bengali voice pack is installed on Windows, setting utterance.lang = 'bn-BD' instructs Chrome / Edge to use the browser's built-in cloud synthesis engine.
